AWS SBG Learning Management System (LMS)

Community & Institutional Project Publicly Launched • Oct 9, 2026 Next.js TypeScript PostgreSQL Prisma ORM Supabase Auth.js (NextAuth) Argon2id Vercel

1. Project Overview & Context

The AWS Student Builder Group (AWS SBG) Learning Management System (LMS) is a centralized educational platform engineered to support student learning across campus at RGUKT Ongole. The platform was officially launched to the student body on October 9, 2026 alongside the organization's official web presence.

Prior to this initiative, student technical learning relied on fragmented communication channels, disconnected tutorial links, and informal note sharing. The LMS unifies the campus technical curriculum into an organized, accessible, and structured portal where students can explore courses, follow modular lessons, watch lecture videos, and track their educational journey in a single dedicated environment.

2. Problem & Objectives

Developing an institutional learning system for an active campus student community presented distinct challenges:

  • > Curriculum Fragmentation: Learning materials were scattered across varied external drives, spreadsheets, and chat groups without clear learning roadmaps.
  • > Lack of Structured Progress Visibility: Students lacked a personalized dashboard to track completed lessons and monitor their course progress.
  • > Secure Access & Onboarding: The platform required credential-based access to safeguard campus learning resources while maintaining a smooth onboarding experience for enrolled student cohorts.

3. Implemented Platform Features

[01] Student Authentication & Dashboard

Credentials-based authentication system safeguarding student sessions. Upon login, students access a clean, distraction-free dashboard showing registered courses, learning pathways, and module progress.

[02] Structured Course & Lesson Hierarchy

Educational content is organized through a relational model: Course → Modules → Lessons. Each lesson presents clear learning objectives, technical walkthroughs, and supporting documentation.

[03] Curated YouTube-Based Video Learning

Built-in video delivery supporting validated YouTube lesson embeddings. Ingests normalized video identifiers and renders them via responsive, privacy-conscious players embedded directly within the lesson interface.

[04] Persisted Learning Progress

Student lesson completions and module milestones are persisted directly to PostgreSQL via Prisma ORM, enabling students to resume their learning uninterrupted across sessions and devices.

[05] High-Level Cohort Onboarding

An organized onboarding workflow enabling students to register interest through an application process, followed by administrative cohort verification and credential delivery for secure access.

4. Technical Architecture

The LMS is architected as a modern, type-safe full-stack web application with distinct separation of presentation, server-side business logic, authentication, and relational persistence:

Tier 1: Presentation

Next.js & TypeScript

Server-rendered layouts & interactive client components. Fully responsive across desktop and mobile.

Tier 2: Auth Layer

Auth.js / NextAuth

Credentials provider with Argon2id cryptographic hashing & session-based route protection.

Tier 3: Data Access

Prisma ORM

Type-safe schema definitions, database migrations, and structured relationship querying.

Tier 4: Persistence

PostgreSQL (Supabase)

Managed relational storage persisting user records, courses, modules, lessons, and progress data.

> Request Lifecycle Flow

Student Request → Vercel Edge → Next.js Server / Route Middleware (Auth.js session verification) → Server Action / API Handler → Prisma ORM → PostgreSQL (Supabase) → Rendered UI + Embed Video Player.

6. Security & Engineering Considerations

From a software engineering and cybersecurity perspective, key defensive choices were incorporated into the architecture:

  • > Robust Password Hashing (Argon2id): Passwords are protected using Argon2id, the state-of-the-art memory-hard hashing algorithm resistant to GPU-accelerated and ASIC brute-force attacks.
  • > Authentication & Route Boundary Protection: Protected dashboard and course routes require valid server-verified session tokens. Requests without active authentication are denied at the middleware boundary.
  • > Type-Safe Data Layer: Utilizing Prisma ORM with strict TypeScript definitions avoids raw string concatenation, effectively neutralizing SQL injection risks and maintaining data contract consistency.
  • > Input Normalization & Video Sanitization: Course video links undergo server-side validation to ensure only authorized video identifiers are embedded, mitigating cross-site scripting (XSS) concerns in video rendering.
